# 双系统时区问题

Arch Linux 与 Windows 双系统下时间不一致，根因是两者对硬件时钟（RTC）的解读不同。常见现象：进入 Windows 后时间显示错误、返回 Linux 后也不对、日志出现 `RTC 时间从未更新` 警告、NTP 同步异常。

## 1 根本原因

- **Linux** 默认把硬件时钟（RTC）当作 **UTC**，再按本地时区换算显示。
- **Windows** 默认把 RTC 当作 **本地时间（Local Time）**，直接读、不换算。
- 两者互相改写 RTC，切换系统就出现时区偏移量误差（东八区差 8 小时）。

## 2 解决方案

### 2.1 方案一：统一使用 UTC（推荐，最干净）

两个系统都按 UTC 处理 RTC。

Linux：

```bash
sudo timedatectl set-local-rtc 0     # 硬件时钟用 UTC
sudo timedatectl set-ntp true        # 启用 NTP
timedatectl status
```

Windows（管理员 cmd）：

```cmd
reg add "HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1
```

改完重启生效。

### 2.2 方案二：统一使用本地时间（不想改 Windows 时）

Linux 改成按本地时间读 RTC，Windows 保持默认。

```bash
sudo timedatectl set-local-rtc 1 --adjust-system-clock
cat /etc/adjtime          # 第三行应为 LOCAL
timedatectl status
```

> [!warning] 夏令时隐患
> 用本地时间时，有夏令时的地区可能出现二次偏移，非 DST 地区无碍。

### 2.3 方案三：手动同步（临时凑合）

Windows → Linux 后：

```bash
sudo timedatectl set-ntp true
sudo ntpd -gq             # 或 sudo hwclock --hctosys
```

Linux → Windows 后（管理员 cmd）：

```cmd
w32tm /resync
```

## 3 验证

- **Linux**：`timedatectl status`，看 `RTC in local TZ` —— `no` = 用 UTC（推荐），`yes` = 用本地时间。
- **Windows**：`regedit` 查 `HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\TimeZoneInformation` 的 `RealTimeIsUniversal` —— `1` = UTC，不存在或 `0` = 本地时间。

## 4 最佳实践

- 首选**统一 UTC**，最可靠。
- 虚拟机环境建议始终用 UTC；服务器必须用 UTC。
- 用本地时间的方案要注意夏令时。

## 5 常见问题

- **改后仍不准？** 重启使更改完全生效；并检查时区：`sudo timedatectl set-timezone Asia/Shanghai`。
- **为什么差 8 小时？** 一个系统按 UTC、一个按本地时间（如北京时间 UTC+8）。
- **怎么看当前硬件时钟？** `sudo hwclock --show`。
